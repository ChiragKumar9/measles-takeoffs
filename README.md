# Predicting county-level measles cases

*This repository provides the analytical code and methods for the manuscript "Epidemiologic shifts predict spatial patterns of measles re-emergence in the United States. https://doi.org/10.64898/2026.10.14.26365590*.

## Description

- Analyze determinants of county-level measles outbreaks in the US from 2010 onwards, including how determinants have changed over time.
- Account for spatial relationships between counties.
- Develop and validate predictive models for outbreak risk.
- Project future risk using validated models, including impacts under potential interventions.

## How to run model code

1. This repo uses the `uv` package manager for Python. Please install [`uv`](https://docs.astral.sh/uv/getting-started/installation/).
2. A US Census API Key is also required. Keys can be requested [here](https://api.census.gov/data/key_signup.html). Please make a `.env` file in the repo root (akin to the `.env.example` file) and put your Census Key in the file as `CENSUS_API_KEY`.
3. Run `uv sync` from the project directory to get the necessary dependencies in an environment.
4. Run analysis scripts using `uv run [PATH TO FILE TO RUN]`. Alternatively, you can open a Python session with `uv run ipython` in your terminal to run code interactively.

Notes:

- `00_explore_data.py` must be run with `--five-year`. Without it the data lack the five-year coverage columns that scripts 02 and 04 need. The flag also changes the row order of `outbreaks_vaccinations_cleaned_imputed.csv`, so after switching it, rerun script 01 and the models.
- The model draws in `outputs/` (the `samples_*`, `predictive_*`, `risk_projections_*` and `posterior_samples_*` files) are compressed `.npz` files written and read by `src/outbreak_size/samples_io.py`; they hold the same values and dtypes as the pickles they replaced and take much less disk space. The importation tables, the mechanistic model's `final_outbreak_size_predictions_*`, `import_scaler_2025` and `agreement_flags_and_truth` are still `.pkl` files.
- Script 07 fits one of the 36 statistical models of the table script: the headline statistical model, the one you chose with `06b_choose_headline_models.py` (read from `outputs/headline_models.json`; no script picks a model from the tables by itself, so rerunning the table script does not change what 07 fits). It prints the model, when and why it was chosen when it starts, stops if the file is missing, and saves a record of the model it fitted next to its draws (`outputs/risk_projection_model_globals_prior_sd=*.json`). Script 11 builds the same model from that record, never from the choice file, and prints its terms (with a warning if it has no exemption terms). If you choose another model, rerun 07 (and 09 and 11). Script 07 stops, and does not write its projections, if its fit has an r_hat above 1.01; the draws are then in a `_not_converged` file.
- The CAR (spatial) term is sampled in the form of `params.yml` (`inferential_non_centered_car` for 02 and 03, `validation_non_centered_car` for 06, `projection_non_centered_car` for 07): a fit that starts centred and has an r_hat above 1.01 is refit non-centred (the same model), and the diagnostics of every fit are written to `outputs/convergence_*.csv`. Script 11 uses the form of the draws of script 07. The prior of the scales of the spatial terms is `spatial_sigma_prior_scale` in `params.yml`, the same in 02, 03, 06 and 07.
- `query_california_population.py` is a one-off helper that is not part of the pipeline: no script reads the file it writes.
- **Years.** The outbreak year Y uses the vaccination data of the school year Y-1 (in the data, `year` is the first year of the school year, so `year` 2025 is 2025-26). The cases of 2026 are part of the year (the case file runs to the autumn, and does not say which cases were imported, so the 2026 outcome includes imports). Scripts 02, 03 and 04 and the figures that read them stay on 2011-2025. 2026 is a validation year for the headline model only (`06_rolling_validation.py --headline-2026`, `table_headline_2026_validation.py`); script 07 trains on 2019-2026 and projects 2027-2030, so the map of the validation figure is conditioned on the cases of 2026 as it used to be on those of 2025.
- **Imports.** The imports of 2026 and of every later year are conditioned on the imports known to 2025: the rows of 2027 on join the `validation_year == 2026`, `type == "projection"` importation rows (`IMPORT_CONDITIONING_VALIDATION_YEAR` in `src/outbreak_size/importation.py`), and there are no importation rows of 2027. Script 08 stops if a known import year after 2025 appears.
- **Scenario years.** A scenario's value for the outbreak year Y is the baseline value plus the slope times the years from the baseline year to the school year Y-1 (Y-1 and not Y), and the targeted improvement reaches 95% at the school year before its end year.
- **Trended values.** A value observed before the school year it stands for is moved to it along a slope, once: the year file of year Y holds each county's value at school year Y-1, and the scenarios start from the value at the last known school year (so `no_change` holds that value and the baseline scenario of 2027 equals the year file of 2027). A slope is the series' own since 2020 (at least two school years), else its state's (the CDC's), else the national average (an unweighted mean of the counties' own slopes, from the data before the year only); the nonmedical exemption of a ban state never rises. A county with nothing since 2020 but older county values (Montana's counties, Hamilton County NY) starts from its latest older value and takes its slope over the same number of school years as the rule since 2020 spans in that fold, counted back from it. Imputed data (the `_imputed` datasets) are never trended.
- **Census answers are kept.** Scripts 00, 05 and 08 ask the Census one county and year at a time, which is slow. Each answer is saved as it arrives in `outputs/census_cache.sqlite` (not in git), under the county and the ACS year the query really asks (the census of the year BEFORE the outbreak year, as for the vaccination data, see `src/outbreak_size/data_year.py`; every year after `LATEST_ACS5_YEAR` = 2024 asks 2024, and Connecticut stops at 2021). So script 00 asks each county and year once (for both sets of files), script 05 asks 2024 once for the outbreak years 2025-2027, a rerun of either only asks what is new, and a run that stops (a lost connection) can simply be started again and goes on from the answers it has. The requests are sent 8 at a time (`CENSUS_WORKERS` in `src/outbreak_size/utils.py`; in a test with the real API, 40 counties took 2.8 s against 15.3 s one at a time, with identical tables), each place and year once; a query that fails is tried 3 times and then stops the run, keeping the answers that arrived. A query that fails saves nothing. The file is checked against the code of the query: if the fields asked change, the old answers are not used. To ask the Census again for everything, delete the file.
- **Leave-one-cluster-out fits.** Script 02 also fits its baseline All covariates model of 2021-2025 (no cutoff, neighbors or five-year coverage) without one cluster of 2025 outbreaks at a time (the three clusters of panel d of `figure_predicting_county_level_outbreaks.py`): the places of the cluster are dropped from 2025 only, and the model is refit on the rest of the years 2021-2025 with its adjacency matrix rebuilt for the places that remain. `figure_supplemental_sensitivity_analyses.py` plots them (panel f). The fits have the settings and the seed of the main fits, and their files carry `_leave_out_west_texas_nm`, `_leave_out_upstate_sc` or `_leave_out_utah_arizona` before the extension, so the main files are not touched. Each prints how many places, rows and outbreak cases it leaves out. The clusters are found from the cases of all the counties (the data of 00 before the vaccine data are required), as in the figure.
- **Coefficient figures.** With `covariate_scale: natural` (params.yml) a coefficient of the vaccination covariates is per SD of the log susceptible fraction (coverage) or of log(1 + exemption %), so the figures that plot coefficients convert them with `src/outbreak_size/coverage_effect.py` (the SD is that of the covariate on the scale of the fit). Every axis is the % change in outbreak size per 1 percentage point of coverage (or of exemptions). On the natural scale that depends on the coverage it starts from (a point matters more where coverage is high) and on `mmr_effectiveness`, so it is averaged over the same reference county-years for every period, year, state and fit that is compared (all of 2011-2025, each at its own coverage), so that a comparison is of the fitted elasticities and not of the coverage of the rows. The printouts of `figure_coverage_predictability_changes_over_time.py` also give the elasticity, the % change per 1% increase in susceptibility, the same per-pp effect over each period's own county-years, the change in cases per pp for the average outbreak, and an empirical two-sided p-value of 2021-2025 against 2011-2020 (every draw of one fit against every draw of the other). That script also writes `figure_supplemental_coverage_effect_linear_scale` (a: panel c from the raw-scale fits of 02; b: the Poisson-likelihood All covariates fit, which 02 now fits in both periods).
- **Running script 06.** The full rolling validation is 168 statistical fits (14 training windows x 3 sets of covariates x pooled or not x spatial or not, each with 4 MCMC chains on the 4 CPU devices the script asks JAX for) and the mechanistic fits. A fit is written to `outputs/` when it finishes (first to a `.part` file, then renamed), and a rerun skips every file that exists, so a stopped run is simply started again. Fits take from minutes (non-spatial) up to at most about 2 hours (the longest fits, the spatial All covariates ones) and use at most about 5 GB of memory (the same fits; the non-spatial ones need about 1.5 GB). These are maximum values, for the longest fits, on a standard laptop; most fits are much faster and lighter. The whole set still takes days on one machine. JAX's memory grows over a long process: if memory is short, start the script again after every saved fit (it exits cleanly when it has nothing left to fit). The record of each fit's diagnostics is `outputs/convergence_06_rolling_validation.csv`; a fit that never reaches r_hat 1.01 is kept and its row says so, and the tables use it.
- **Rerunning script 06.** It skips a sample file that already exists, so move the old files of `outputs/` that it writes aside before rerunning it after the data changed.
- **Doses of the interventions** (`src/outbreak_size/doses.py`; the columns of S5a and S5b). A county's kindergarten cohort is a fifth of its population aged 5-9 (ACS B01001, in the vintage that script 05 used for that county's population: the census of the year before the outbreak year, 2024 for every year after it, and 2021 for Connecticut; the code checks that the vintage's total population is the county's `population` column). The doses of a county and year are `2 doses x cohort x coverage increase / 100`, where the coverage increase (percentage points) is the intervention's MMR coverage minus the same scenario's baseline coverage in that year, floored at 0 (an intervention that leaves a county's coverage lower adds no doses, not negative ones). It assumes the children whose coverage rises were not vaccinated and need the whole series. The tables have the cohort, then for each outbreak year 2027-2030 the coverage increase and the doses, and the cumulative doses over 2027-2030 (the interventions start in 2027); the state table sums the doses of its counties, each floored at county level. `figure_supplemental_kindergarten_cohort.py` checks the cohort against counted kindergartners.

## School-level vaccination data

School-level MMR coverage from three sources is combined into a school-level file and a county-level file (rates in percent, 0-100). The county file feeds the school SD fits of `02_fit_hierarchical_poisson.py` and panel d of `figure_predicting_county_level_outbreaks.py`.

- Sources: Chen & Bento ([PMID 42613442](https://pubmed.ncbi.nlm.nih.gov/42613442/); the per-state school files `data/schools/<STATE>_school.rds` from Zenodo, [10.5281/zenodo.19430274](https://doi.org/10.5281/zenodo.19430274) and [10.5281/zenodo.20174071](https://doi.org/10.5281/zenodo.20174071), CC-BY-4.0, please cite the paper), the Washington Post school file `data/vaxrates_schools.csv` (one school year per state; check its terms of use before redistributing derived files), and the state files, school-level files published by states (the school-data zip `data/drive-download-*.zip`). The county boundaries are the Census 500k cartographic file in `data/cb_2020_us_county_500k/`.
- To build the files, from the repo root, after step 1 and in this order (step 2 of the table): `Rscript --vanilla analysis/export_school_rds.R` (base R only; reads `data/schools/<STATE>_school.rds` and writes `data/schools/school_points_raw.csv`), `uv run analysis/read_school_state_files.py` (reads the school-level state files from the one `data/drive-download-*.zip`, without unzipping it, and writes `data/schools/state_files_schools.csv`, which the next script uses if it exists), `uv run analysis/assemble_school_vaccination.py`, then `uv run analysis/check_school_vaccination.py` (compares the result with what was expected and with `data/processed_vaccinations_data.csv`, and exits with 1 if anything differs). `pdftotext` (poppler) must be installed for the state files that are PDFs (South Carolina, Iowa and Maine).
- They write `data/school_vaccination_schools.csv` and `data/school_vaccination_counties.csv`, and the QC log, the source of each state and school year (`source_by_state_year.csv`) and the checks in `outputs/school_vaccination/`. `uv run analysis/table_school_data_availability.py` (after those, and step 1) then writes `outputs/school_vaccination/school_data_availability_by_year.csv`: the school-level data available in each year and the measles cases in the counties that have it.
- The rules (the module docstring of `src/outbreak_size/school_vaccination.py` has them in full): each state and school year has one source, the Washington Post, else Chen & Bento, else a state file; the Washington Post is used only if it has at least `wapo_min_share_of_chen_bento` (params.yml, 90%) of Chen & Bento's schools, and a state file only if it has that share of the schools of the nearest year of another source. A rate outside 0-100 is missing; an enrollment of 0 makes enrollment and rate missing; a Chen & Bento rate of exactly 0 with no enrollment is missing; a district row at exactly 0% is missing; identical records (same point and rate, and for the Washington Post the same name) are one school unless the enrollments differ or another year shows two schools at the point; a Washington Post school whose label county is more than 20 km from its point is dropped. A state that reports a school as a band ("≥98%", ">95%") has its band rows read at the middle of the band in the state files; Chen & Bento and the Washington Post record such a school at the threshold (98) and are used as they are.
- The constants are in `params.yml` (`school_vaccination`), and the definitions of the county-level columns in the docstring of the `county_file` function.
- Panel d of the county-level outbreak figure weights the school SD by the kindergarten counts of the 2024-25 Common Core of Data (NCES, public schools and districts): `uv run analysis/read_ccd_enrollment.py --raw-dir DIR` (the URLs of the raw files are in its docstring) writes `data/ccd_2024_25_schools.csv` and `data/ccd_2024_25_districts.csv`, and `src/outbreak_size/ccd_enrollment.py` matches our school rows to them (the same name in the county or within 100 m; Texas districts by name) and has the weighting rules. A county is weighted only where its schools are matched; the other counties keep the unweighted SD. Run it before `figure_predicting_county_level_outbreaks.py`, which stops if the CCD files are missing.

## How to run the tests

We include a test suite for model functions and data processing code. To run the test suite, run `uv run --group test pytest` from project root. The tests use no data files (the few that check a real file in `data/`, such as the case-assignment files, skip themselves when it is absent), and they run on every push to GitHub ([`.github/workflows/python-test.yml`](.github/workflows/python-test.yml)).
